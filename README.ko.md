# eg2-langid

[English](README.md) | **한국어**

EmbeddingGemma 2 오디오 임베딩 위에 얹은 **경량 언어 식별(language identification)** 패키지입니다.

768차원 오디오 임베딩 공간 위의 **187KB 선형 분류기** 하나로 **29개 언어**를 판정합니다.
LLM 호출 없이 CPU만으로 동작합니다. 임베딩 모델은 **패키지에 포함되어 있지 않으며**, 이미 구동 중인
EmbeddingGemma 2 ONNX 런타임에 붙어서 원본 오디오 또는 미리 계산된 벡터를 받아 동작합니다.

## 특징

- **29개 언어** (정답 라벨로 검증된 22개 + VoxLingua107에서 편입한 7개)
- **아티팩트 하나 187KB** — 필수 의존성은 `numpy` 뿐입니다
- **세 가지 통합 레벨**: 벡터 입력 · 오디오 + 임베더 콜백 · 선택적 모델 어댑터
- **미지 언어 게이트** — 알려진 언어 어디에도 맞지 않는 오디오를 거부합니다
- **라이브 데스크톱 위젯** — PC에서 재생 중인 소리의 언어를 5초 창으로 표시합니다
- **스트리밍 구조** — 임베딩은 계산 → 판정 → 폐기. 디스크에 아무것도 쓰지 않습니다

## 실측 성능

| 평가 | 결과 |
|---|---|
| 홀드아웃 gold (FLEURS test, 22언어 × 100건) | **0.9868** (2,171 / 2,200) |
| id/ms 쌍을 제외한 정확도 | **99.95%** (2,000건 중 1건 오답) |
| 5초 창 vs 전체 클립 | **98.2%** vs 97.7% |
| 3초 / 2초 / 1초 창 | 90.5% / 77.3% / 47.0% |
| 미지 언어 거부율 (오거부 5.5% 기준) | 37.5% |
| 임베딩 + 판정 지연 (5초 오디오) | 약 0.4초 (CPU 4스레드) |

남은 오답은 한 쌍에 집중됩니다 — 말레이어 ↔ 인도네시아어 (오답 29건 중 28건).
두 언어는 상호이해 가능성이 높아, 낭독체 음성만으로는 본질적으로 모호한 구간이 실재합니다.

## 설치

```bash
pip install numpy            # 코어 패키지 — 이게 전부입니다
pip install pyaudiowpatch    # 라이브 데스크톱 위젯을 쓸 때만
```

임베딩 모델은 실행 시 필요하지만 **이 저장소에 포함되어 있지 않습니다**.
`mmal4/`, `model-src/`, `src/` 를 담은 기존 배포 디렉터리를 지정해 주세요.

```bash
export EG2_MMAL4_DIR=/path/to/deploy
```

## 사용법

### 1. 벡터 입력 (가장 가벼운 방식)

```python
from eg2_langid import LanguageIdentifier

li = LanguageIdentifier()
r = li.detect(vec_768d)
print(r)                 # "ko_kr (97%)"
print(r.lang, r.unknown, r.confidence)
```

### 2. 오디오 입력 + 직접 만든 임베더

```python
r = li.detect_audio(pcm_float32_16k, embed_fn=my_embedder, window_sec=5.0, hop_sec=1.0)
print(r.distribution)    # {'ko_kr': 0.8, 'en_us': 0.2}  — 창별 투표 비중
```

### 3. 내장 어댑터 사용 (모델 필요)

```python
from eg2_langid.adapters.gemma2 import make_embedder

embed = make_embedder()                                   # EG2_MMAL4_DIR 를 읽습니다
r = li.detect_audio(pcm_float32_16k, embed_fn=embed, window_sec=5.0)
```

### Result 필드

| 필드 | 의미 |
|---|---|
| `lang` / `label` | 승자 클래스(라벨은 {hi, ur} 그룹 표기 적용). 거부되면 `None` |
| `confidence` | **미지언어 게이트 임계 대비 여유** — `0`이면 간신히 통과, `1`이면 여유로움. 정확도 수치가 아닙니다 |
| `p_correct` | **이 판정이 맞을 확률**(gold margin 캘리브레이션). 위젯이 표시하는 값 |
| `margin` | 1위 점수 − 2위 점수 |
| `unknown` | 29개 언어 밖으로 판정되어 게이트가 거부 |
| `distribution` | 오디오가 한 창보다 길 때 창별 투표 비중 |

짧은 클립은 `confidence`가 0.02여도 정답일 수 있으므로, 화면에는 `p_correct`를 쓰세요.

### 음악 / 효과음 판정

5초 창을 **발화 포함 여부**로도 평가합니다. 말소리가 없으면 언어 대신 `kind='music'` 또는
`kind='sfx'`가 반환되고, 위젯은 (엉뚱한) 언어 대신 **음악** / **효과음**을 표시합니다.

```python
r = li.detect_audio(pcm, embed_fn=embed, vad_fn=vad)   # vad는 선택
r.kind          # 'speech' | 'music' | 'sfx'
r.p_nonspeech   # 0~1
```

| 설정 | 발화 오탐 | 기악 | 보컬 음악 | 효과음 |
|---|---|---|---|---|
| **VAD 사용** (0.70) | **0.0%** | 97.5% | 75.0% | 93.6% |
| VAD 없음, numpy만 (0.85) | 0.0% | 71.6% | 68.3% | 53.2% |

파일 단위 교차검증 기준입니다 — 발화 129크롭(8개 언어 FLEURS), 기악 22곡, 보컬 20곡,
Windows 효과음 70개. `vad`는 `eg2_langid.adapters.silero_vad.make_vad()`로 만듭니다
(`onnxruntime` 필요, 모델이 없으면 numpy 경로로도 동작).

**실측 한계**
- 가창은 발화와 완전히 분리되지 않습니다 — 보컬 트랙의 75%만 음악으로 잡히고, 나머지는 언어로
  표시됩니다(가사가 실제로 그 언어이므로 틀린 판정은 아닙니다).
- 음악과 효과음은 약 20%가 서로 혼동됩니다(효과음 재현율 78.7%) — 알람이 *음악*으로 표시될 수 있습니다.
- 원본 파일 112개로 학습했습니다. 말소리가 많이 섞인 징글은 여전히 언어로 읽힐 수 있습니다.

**이 헤드는 언어 프로브와 분리되어 있습니다** — 원파형에서 뽑은 특징(VAD 비율, 2~8Hz 포락선 변조,
스펙트럼 중심·평탄도·플럭스, RMS 변화)에 11개 계수의 로지스틱 회귀만 적용하므로 29개 언어 정확도에는
영향을 주지 않습니다(gold 0.9868 유지).

### 라이브 데스크톱 위젯

시스템 출력음을 WASAPI 루프백으로 캡처해 5초 링버퍼를 유지하고, 2초마다 다시 판정합니다.

```bash
python app/live_langid.py
```

창을 아무 곳이나 드래그해 이동하고, 우측 상단 **×** 를 누르면 종료됩니다. 우클릭 메뉴에서 일시정지/종료도 가능합니다.

**소리가 없으면 연산하지 않습니다.** 새 오디오가 실제로 들어왔을 때만 임베딩하므로, 무음 상태의
CPU 사용률은 **0%** 입니다(실측). 재생 중에는 **약 1코어**를 씁니다(2초 주기·4코어 기준 실측 99%,
1초 주기에서 210%였던 값). 재생이 멈추면 마지막 판정을 그대로 두고 같은 버퍼를 다시 계산하지 않습니다.

| 환경변수 | 기본값 | 의미 |
|---|---|---|
| `EG2_HOP` | `2.0` | 판정 주기(초) — CPU를 좌우하는 주 손잡이 |
| `EG2_IDLE_HOP` | `4.0` | 무음일 때의 폴링 주기 |
| `EG2_THREADS` | `2` | 임베딩 세션의 ONNX Runtime 스레드 수 |
| `EG2_DEBUG` | — | 틱마다 `rms`·생략 사유를 출력 |
| `EG2_LANG` | OS 로캘 | 위젯 표시 언어: `en` 또는 `ko` |

위젯은 **기본이 영어**이고, Windows 표시 언어가 한국어이면(`GetUserDefaultUILanguage()` = 0x0412)
**한국어로 자동 전환**됩니다. 언어 이름과 상태 문구가 모두 그 선택을 따릅니다.
`EG2_LANG=ko` / `EG2_LANG=en` 으로 강제할 수 있습니다. 화면의 퍼센트는 `p_correct`(정답 확률)입니다.

## 저장소 구조

```
eg2_langid/          배포 패키지 (numpy만, 모델 가중치 미포함)

tools/               아티팩트 생성 + 참조 임베더

```

`tools/export_artifact.py` 는 로컬 데이터 디렉터리에서 `model.npz` 를 다시 생성하며,
보고된 gold 정확도를 재현합니다.

## 모델 및 양자화

프로브는 768차원 L2 정규화 오디오 임베딩을 입력으로 받습니다. 임베딩 모델은 패키지에 포함되지
않으며, sentence-embedding 출력을 내보내는 EmbeddingGemma 2 ONNX 빌드라면 무엇이든 붙일 수 있습니다.

**이 문서의 수치를 측정한 구성**

| 항목 | 값 |
|---|---|
| 가중치 형식 | **int8 블록 양자화 — `MatMulNBits` `bits=8`, `accuracy_level=4`** ("q8-al4") |
| 파일 | 오디오 인코더 340MB + 백본 314MB (**654MB**) |
| 상주 메모리 | 약 0.6GB |
| 지연 | 27초 청크당 0.4~1.2초 (CPU 4스레드) |

배포본을 노드 단위로 확인하면 오디오 인코더에 `MatMulNBits`(bits=8) 123개, 백본에 146개가 있습니다 —
즉 **int8 가중치**이며, 업스트림이 배포하는 `*_quantized.onnx` 계열과 같은 구성입니다.

**CPU에서 q8을 쓰는 이유**

| 변형 | 디스크 | CPU 메모리 | 비고 |
|---|---|---|---|
| **q8 (int8 블록)** | 654MB | **양자화 세트 중 최소** | 이 문서의 모든 수치를 낸 구성 |
| q4 (int4 블록) | 363MB | 비슷함 | 업스트림에 존재(`*_q4.onnx`). 디스크만 작고 이 프로젝트에서 미측정 |
| q4f16 | 327MB | **더 큼** | fp16 활성화 유지 — 이 모델 계열 실측 commit ≈559MB (q8은 ≈466MB) |
| fp16 | 1.1GB | 최대 | 품질 기준선 |

CPU에서는 **q8이 균형점**입니다. int8 가중치 + int8 연산(`accuracy_level=4`)이라 파일이 더 커도
활성화가 작게 유지돼 실사용 메모리는 q4f16보다 적습니다. q4가 이기는 건 디스크 크기뿐입니다.

**양자화 가중치를 GPU 실행 프로바이더에 올리지 마세요.** `MatMulNBits` 는 DirectML·CUDA 커널이
없어 해당 노드가 **조용히 CPU로 폴백**됩니다. GPU 메모리는 잡아먹고 속도 이득은 얻지 못합니다.

> 이 문서의 모든 수치는 q8-al4 빌드 기준입니다. 업스트림에는 fp32 / fp16 / q4 / q4f16 빌드도
> 있으므로 파일 교체로 바꿀 수 있고, 어댑터는 양자화 방식과 무관하게 동작합니다.

## 한계

- 라이브 위젯은 **Windows에서만 검증**했습니다 (WASAPI 루프백). 패키지 자체는 플랫폼 독립적입니다.
- Windows 캡처는 장치 레이트(예: 192kHz)로 받아 메모리에서 16kHz로 리샘플링합니다.
- 창이 3초보다 짧아지면 정확도가 급격히 떨어집니다. **5초를 권장**합니다.
- 음악·비발화는 전용 클래스가 아니라 게이트가 "알 수 없음"으로 처리합니다.
- 말레이어/인도네시아어 모호성은 언어 자체의 성질이라 데이터를 늘려도 완전히 해결되지 않습니다.
